# Отчёт по коммитам изменений с задачами DEV

Требуются Python 3.9+ и Git в PATH. Дополнительные библиотеки и Excel не нужны. Для `--fetch` требуется доступ к Git-серверу, в том числе VPN для корпоративной сети.

Скрипт хранится в репозитории `devops`, а анализируемый репозиторий задаётся параметром `--repo` (по умолчанию текущая папка).

Из корня соседнего репозитория `erp` в PowerShell:

```powershell
python ..\devops\scripts\audit\export_master_dev_report.py --repo . --from 2026-01-01 --to 2026-09-30 --output .\DEV_report.xlsx
```

Если Python установлен через Windows Launcher, вместо `python` можно использовать `py -3`.

Для другого репозитория или ветки:

```powershell
python ..\devops\scripts\audit\export_master_dev_report.py --repo "D:\work\РТИТС\erp" --branch origin/master --from 01.01.2026 --to 30.09.2026 --output .\DEV_report.xlsx
```

- `--from` и `--to` — обязательные даты начала и конца, обе включительно. Форматы: `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`.
- `--repo` — путь к репозиторию; по умолчанию текущая папка.
- `--branch` — ветка или Git ref; по умолчанию `master`.
- `--fetch` — перед формированием отчёта загрузить указанную ветку с `origin` и использовать обновлённую `origin/<ветка>`. По умолчанию загружается `master`; с `--branch origin/master` результат тот же. Поддерживаются имена веток, а не теги или SHA. При ошибке загрузки отчёт не формируется, существующий выходной файл сохраняется.
- `--output` — имя XLSX; по умолчанию `DEV_report_<начало>_<конец>.xlsx` в текущей папке. Существующий файл с таким именем заменяется.

В файле два листа: «Коммиты» и «Задачи». В шапке явно разделены количество коммитов изменений и количество уникальных задач. Заголовки закреплены, таблицы снабжены фильтрами. Полные SHA сохранены для проверки.

Номера задач на обоих листах — кликабельные ссылки `https://1c-jira.rtits.ru/browse/DEV-<номер>`. Запросы к Jira не выполняются. Если коммит упоминает несколько задач, первая стоит в столбце «Задача DEV», остальные — в столбцах «Задача DEV 2», «Задача DEV 3» и далее справа. Каждая задача имеет отдельную ссылку; одна строка по-прежнему соответствует одному коммиту.

Чтобы сформировать отчёт по актуальному состоянию серверной ветки через VPN, из корня `erp`:

```powershell
python ..\devops\scripts\audit\export_master_dev_report.py --repo . --fetch --from 2026-01-01 --to 2026-09-30 --output .\DEV_report_2026.xlsx
```

Та же команда из корня репозитория `devops`:

```powershell
python .\scripts\audit\export_master_dev_report.py --repo ..\erp --fetch --from 2026-01-01 --to 2026-09-30 --output .\DEV_report_2026.xlsx
```

Период определяется **по первому попаданию SHA в выбранную ветку**, а не по дате создания коммита. Для каждого коммита в основной цепочке ветки вычисляется разность истории с его первым родителем. Поэтому старый коммит, включённый в релиз в выбранном периоде, попадёт в отчёт. Дата коммита — дата committer из Git; автор — поле author.

Коммиты с двумя или более родителями исключены. Остаются только коммиты с упоминаниями `DEV-<номер>` в теме или теле сообщения. Регистр не учитывается. Одна строка на SHA, даже если в нём несколько задач. На листе «Задачи» одна строка на номер DEV; суммы количества коммитов по задачам могут превышать общее число коммитов, если один SHA упоминает несколько задач. Упоминания в сообщении не подтверждают статус задачи в трекере. Коммиты отмены изменений также входят в историю.

Все даты приведены к Москве (UTC+3). В ячейках они записаны текстом `ГГГГ-ММ-ДД ЧЧ:ММ`, чтобы оставаться читаемыми в Excel и предпросмотре. Такой порядок также позволяет правильно сортировать даты как текст.

Без `--fetch` скрипт читает только локальную историю. С `--fetch` он обновляет удалённый ref `origin/<ветка>`; локальная `master`, текущая ветка и исходники остаются без изменений. Если обновление отклонено Git (например, из-за недоступности сервера или переписанной истории), скрипт завершится с ошибкой вместо построения отчёта по старому ref. При неполной истории (`shallow clone`) скрипт остановится с ошибкой. Пустой период создаёт файл с нулевыми итогами и заголовками.
